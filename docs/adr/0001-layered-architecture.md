# ADR-0001: Емхана жүйесінің қабатты архитектурасы

- Status: accepted
- Date: 2026-09-10
- Deciders: <Әлішер, Жұлдызхан>

## Context
Емхана — қабылдауға жазылу мен кезекті басқаратын жүйе. Пациент дәрігерлер тізімі мен бос уақыттарды көріп,
дәрігерге жазылады, қажет болса жазылудан бас тартады және қабылдау алдында SMS, email немесе Telegram арқылы
еске салғыш алады. Тіркеуші келген пациентке кезек талонын береді, дәрігер пациентті кезектен шақырады,
ал холлдағы кезек экраны өзі жаңарып отырады. Жүйеде төрт рөл бар: пациент, тіркеуші, дәрігер және әкімші.

## Options considered
1. Simple Layered Architecture (қарапайым қабатты архитектура)
   + Pros: түсіну және жасау оңай, интерфейсті, бизнес-логиканы және деректерді бір-бірінен бөледі.
   - Cons: қабаттар арасында тығыз байланыс болуы мүмкін, модуль шекаралары қатаң емес.

2. Clean Architecture
   + Pros: бизнес-логика фреймворктар мен сыртқы жүйелерге тәуелсіз болады.
   - Cons: шағын Java жобасы үшін тым көп абстракция және артық күрделілік.

3. Microservices Architecture
   + Pros: әр сервис бөлек іске қосылады, масштабтау оңай.
   - Cons: желілік байланыс, сервистерді үйлестіру және қосымша инфрақұрылым қажет.

4. Modular Monolith with Hexagonal Architecture
   + Pros: модуль шекаралары анық, бизнес-логика оқшауланған, тесттеу оңай және икемді.
   - Cons: интерфейстер көбейеді, тәуелділіктерді мұқият басқару керек.

## Decision
We chose Simple Layered Architecture — қарапайым қабатты архитектураны таңдадық.

Қосымша төрт негізгі қабатқа бөлінеді:

Presentation Layer (ui) — пайдаланушымен консоль арқылы жұмыс істейді: мәзір және дайын демо сценарий.

Business Logic Layer (service) — жазылу, бас тарту және оны кері қайтару, кезек пен талон, еске салғыштар,
дәрігер кестесі және рөлдер бойынша рұқсатты тексеру.

Domain Layer (domain) — емхананың негізгі ұғымдары: дәрігер, пациент, слот, жазылу, жазылу күйлері
және кезек тәртібінің ережелері.

Data Access Layer (infra) — дәрігерлер, пациенттер, слоттар мен жазылулар туралы деректерді сақтайды
және хабарлама арналарын (SMS, email, Telegram) қосады.

Әр қабаттың өз жауапкершілігі бар. Presentation қабаты Business Logic қабатымен жұмыс істейді,
ал Business Logic қабаты деректерге Data Access қабаты арқылы қол жеткізеді. Бұл ережелерді
`ArchitectureTest` тесті тексереді: ереже бұзылса, жоба құрастырылмайды.

Бұл архитектура құрылымды анық етеді, сонымен бірге жобаны жасауға, түсінуге және көрсетуге қарапайым қалдырады.

## Consequences
Good: әр қабатты бөлек тесттеуге болады; деректерді сақтау тәсілін (жадтан файлға немесе дерекқорға)
бизнес-логиканы өзгертпей ауыстыруға болады; консоль орнына басқа интерфейс қосуға болады.
Bad / cost: кластар саны көбейеді; деректерді қабаттар арасында тасымалдау үшін қосымша кластар керек.
